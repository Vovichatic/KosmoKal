# ВКД-Риск

Прототип поддержки решений для наземной группы планирования внекорабельной
деятельности на МКС. Считает две независимые линии внешнего риска для
конкретного окна работ, сравнивает окна и показывает, на каких именно записях
источников построен каждый вывод.

Допуск к реальной ВКД остаётся за уполномоченными специалистами. Всё, что
считает сервис, — оценка внешней среды на траектории, а не доза человека.

## Быстрый старт

```bash
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env          # ключи не нужны, но пути и таймауты настраиваются

# офлайн-демо на синтетическом SEP-событии, без сети
python -m evarisk.cli --offline --start 2024-05-11T00:00:00 \
    --duration-h 6.5 --search-h 12 --json out.json

# текущая обстановка из открытых источников
python -m evarisk.cli --start 2026-09-18T06:00:00 --duration-h 6.5 --search-h 12

# веб-сервис
uvicorn evarisk.api:app --reload
```

Тесты: `python -m pytest tests -q` (18 проверок, сеть не нужна).

## Что считается

| Линия | Механизм | Расчёт |
| --- | --- | --- |
| A. Космическая погода | SEP + геомагнитная буря | поток GOES → жёсткость обрезания по SGP4 + IGRF → мощность дозы по траектории, взвешенная по фазам ВКД |
| B. MMOD и сближения | микрометеороиды, мусор, TCA | пуассоновская вероятность пробоя `PNP = exp(−F·A·T)` + окно исключения TCA ± 30 мин |

Освещённость и терминатор учитываются как ограничение работ, а не как риск.

## Три графа

1. **Причинный DAG гелиофизики** (`evarisk/risk/fusion.py`) — вспышка является
   общей причиной шкал S, G и R. Объединение идёт через noisy-OR по байесовской
   сети, поэтому связанные предупреждения не увеличивают риск трижды.
2. **Граф фаз ВКД** (`evarisk/windows.py`, `PHASES`) — у преддыхания,
   шлюзования и работы снаружи разные веса уязвимости. Поэтому сдвиг начала на
   30 минут может помочь, даже когда суммарный флюенс за окно почти не меняется.
3. **Граф происхождения** (`evarisk/provenance.py`) — контентно-адресуемый DAG
   от источника до предупреждения. Он же служит структурой дельта-синхронизации:
   имя узла есть хеш содержимого, обмен начинается со сверки корней.

## Архитектура

```
evarisk/
  config.py        настройки из окружения, секретов в коде нет
  provenance.py    Record, Store, меркл-корень, отсечка as_of, lineage
  sources/         получение данных: кеш, ретраи, заморозка, статусы отказа
    base.py        HttpSource: OK / CACHED / FROZEN / DISABLED / FAILED
    swpc.py        GOES-протоны, Kp, предупреждения SWPC
    celestrak.py   GP-элементы МКС, NORAD 25544
  orbit.py         SGP4, геомагнитная широта, жёсткость обрезания, ЮАА
  risk/
    spaceweather.py  доза-прокси по траектории
    mmod.py          PNP и пересечение с TCA
    fusion.py        байесовская сеть + noisy-OR
  windows.py       оценка окна, Парето-фронт, три исхода рекомендации
  report.py        выгрузка: текст + JSON с хешами доказательств
  api.py           FastAPI: /plan, /sources, управление источниками
  cli.py           демонстрационный прогон
```

Получение данных, расчёт и представление разделены: `sources` ничего не знает
о риске, `risk` ничего не знает о HTTP, `api` и `cli` только собирают.

## Исторический режим и временная честность

`Store.as_of(cutoff)` удаляет все узлы с `issued_at > cutoff` до расчёта.
Поздние уточнения остаются доступны отдельно — для проверки результата, но не
для его получения. У каждого узла время публикации и время наблюдения хранятся
раздельно, потому что эпоха орбитальных элементов не равна моменту их выпуска.

Источники, по которым не удаётся восстановить датированный выпуск, помечаются
как непригодные для строгого replay. На сегодня это относится к архиву
сближений: по нему делается честно обозначенный исторический разбор.

## Отказы источников

Отказ никогда не превращается в «воздействие не выявлено». Источник отдаёт
статус, а ранее полученные записи остаются доступны с отметкой возраста.
Квота и ошибка запроса обрабатываются отдельно от отсутствия события.

```bash
curl -X POST localhost:8000/sources/swpc.goes.protons/freeze   # заморозить
curl -X POST localhost:8000/sources/swpc.kp/disable            # отключить
```

Когда свежих данных не хватает по любому из механизмов, полнота падает ниже
порога и сервис возвращает «оснований для выбора недостаточно» вместо
рекомендации.

## Проверка подхода

Сравнение с простым вариантом — «взять последнее наблюдение» и «взять готовое
предупреждение SWPC». Оценивается на периоде с выраженным событием и на
контрольном периоде без него в пределах 1 мая — 30 июня 2024 года.
Проверяемые показатели: ошибка времени начала воздействия, заблаговременность,
пропуски, ложные предупреждения и устойчивость выбора окна к сдвигу отсечки.

## Единицы и границы применимости

* Поток протонов — pfu на геостационаре. Связь с орбитой МКС строится через
  жёсткость обрезания, а не прямым переносом.
* Доза — мкЗв, **прокси-величина** для внешней обстановки за типовым
  экранированием. Переход к дозе конкретного человека требует модели скафандра
  и эксплуатационных данных, которых в открытом доступе нет.
* `Pc` сближения относится к станции и каталожному объекту. Это не вероятность
  попадания фрагмента в космонавта.
* Жёсткость обрезания и множитель ЮАА — приближённые модели, помечаются как
  `team_computation` и отделены от наблюдений и внешних прогнозов.
