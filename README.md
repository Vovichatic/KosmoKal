# KosmoKal

Исследовательский проект для задачи «Прогнозирование внешних рисков и
планирование ВКД на МКС» КосмоХакатона 2026.

Цель решения — помочь аналитику наземной группы сравнивать возможные окна
внекорабельной деятельности по внешней обстановке, видеть происхождение данных
и получать объяснимую рекомендацию. Проект не предназначен для допуска к
реальной ВКД.

## Состояние проекта

В репозитории сохранены исходные документы соревнования, рабочий бриф,
исследовательский Python-прототип и две воспроизводимые ML-линии.

Прототип уже содержит:

- получение текущих данных NOAA SWPC и CelesTrak;
- расчёт траектории МКС по SGP4;
- экспериментальную оценку космической погоды;
- экспериментальную линию MMOD и сближений;
- сравнение окон по Парето-фронту;
- кеширование, статусы источников и граф происхождения данных;
- evidence-based planner с явным `decision_cutoff`, полнотой факторов и
  отказом от рекомендации при критически неполных данных;
- исторический NOAA RSGA replay с фиксированными выпусками и проверкой
  `Issued`-времени;
- расчёт освещённости/тени по SGP4-траектории и live-скрининг SOCRATES;
- CLI, FastAPI и модульные тесты;
- leakage-aware CatBoost для прогноза превышения локального Q99 на горизонте
  6 часов, обученный на архиве 2020–2024;
- признаки NASA DOSTEL/DONKI, NOAA GOES SGPS/XRS и GFZ Kp/Hp/F10.7;
- leakage-safe CatBoost для раннего предупреждения о высоком финальном риске
  сближения по последовательности ESA CDM.

| Линия | Горизонт/срез | Модель | Основной результат |
|---|---|---|---|
| Космическая погода | следующие 6 часов, история до 7 суток | CatBoost classifier | recall 0.856, precision 0.703 |
| Сближения с каталожными объектами | данные не позднее чем за 2 суток до TCA | CatBoost classifier + regressor | recall 0.615, PR-AUC 0.146 |

На полностью отложенных мае–июне 2024 сохранены два улучшенных режима:
aggressive recall **0.8564** при precision **0.7028** и balanced recall
**0.8246** при precision **0.7277**. У balanced-профиля ROC-AUC **0.8442**,
PR-AUC **0.8643**. Подробное сравнение находится в
[`analysis/catboost_timeseries/MODEL_COMPARISON.md`](analysis/catboost_timeseries/MODEL_COMPARISON.md).

Для каталожного космического мусора добавлена отдельная leakage-safe ML-линия
по последовательностям ESA CDM. На test-like holdout CatBoost повышает PR-AUC
относительно последнего известного риска с 0.072 до 0.146 и получает recall
0.615 против 0.538 и F2 0.367 против 0.327. Из-за всего 13 high-risk событий
в holdout результат считается предварительным; детали находятся в
[`analysis/conjunction_ml/README.md`](analysis/conjunction_ml/README.md).

CatBoost применяется только в обучаемых компонентах. Расчёт орбиты выполняет
SGP4, а риск некаталогизированных микрометеороидов должен оцениваться отдельной
физико-статистической моделью потока (например, NASA MEM/ORDEM). Вероятность
сближения каталожного объекта нельзя трактовать как вероятность попадания
частицы в космонавта. Сводная архитектура и правила честной валидации описаны в
[`docs/ML_PIPELINES.md`](docs/ML_PIPELINES.md).

Текущие ограничения:

- коэффициенты радиационного прокси и MMOD пока не откалиброваны;
- офлайн-демо использует синтетическое солнечное событие;
- сближение в CLI задано демонстрационной записью;
- исторические GP-элементы для реконструкции орбиты должны быть добавлены
  отдельным архивом; резервный TLE намеренно не подставляется автоматически;
- прогноз NOAA задаёт вероятность события по суткам, а не момент начала или
  длительность бури;
- SOCRATES покрывает только каталогизированные объекты, а MMOD/MEM/ORDEM не
  оцениваются без верифицированного потока и модели пробития;
- результат нельзя интерпретировать как реальную дозу или разрешение на ВКД.

## Запуск прототипа

После однократной установки зависимостей весь localhost запускается одной командой:

```bash
./scripts/localhost.sh
```

Либо компоненты можно запустить раздельно:

```bash
cd research/eva-risk
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt

# Офлайн-демо на синтетическом событии
python -m evarisk.cli --offline \
  --start 2024-05-11T00:00:00 \
  --duration-h 6.5 \
  --search-h 12 \
  --json out.json

# API
uvicorn evarisk.api:app --reload
```

Во втором терминале запустите интерфейс:

```bash
cd frontend
npm ci
npm run dev
```

Интерфейс будет доступен на `http://localhost:5173`, а Vite проксирует
`/api` в FastAPI на `http://127.0.0.1:8000`. Live-режим получает текущие
источники, а исторический режим использует NOAA RSGA-выпуски, опубликованные не
позднее `decision_cutoff`.

Глобус получает актуальный TLE МКС (NORAD 25544) из CelesTrak и строит
SGP4-траекторию с шагом две минуты на весь период поиска и длительность ВКД.
Оранжевым выделяется выбранное окно, голубым — дальнейший маршрут. Ползунок
перемещает МКС по расчётной шкале и показывает время UTC, широту, долготу и
высоту. Если CelesTrak недоступен, интерфейс явно помечает резервный TLE.

Орбитальный API можно использовать отдельно:

```bash
curl 'http://127.0.0.1:8000/orbit?hours=8&step_s=120&mode=current'
curl -X POST 'http://127.0.0.1:8000/live/refresh'
```

Для исторического режима API принимает даты 1 мая — 30 июня 2024. При
отсутствии подходящих архивных GP-элементов план получает статус
`insufficient_data`, а не скрытый fallback.

### Evidence-based planning API

`POST /plan` принимает `mode=current|historical`, `start`, `duration_h`,
`search_h`, `step_min`, `decision_cutoff`, `scope` и `disabled_sources`.
Ответ содержит окна, полноту факторов, `critical_missing`, статус решения,
хеши provenance и список узлов evidence.

Пример:

```bash
curl -X POST http://127.0.0.1:8000/plan \
  -H 'Content-Type: application/json' \
  -d '{"start":"2024-05-11T00:00:00Z","duration_h":6.5,"search_h":12,"step_min":30,"mode":"historical","decision_cutoff":"2024-05-10T00:00:00Z"}'
```

### Непрерывный live-поток

Пока запущен FastAPI, фоновый сервис обновляет каждый источник по его
заявленной cadence. `GET /live/status` отдаёт свежесть и статусы, `GET /live/snapshot`
— весь нормализованный срез с хешами provenance.

Workflow `.github/workflows/live-snapshot.yml` каждые 15 минут публикует
`latest.json` в отдельную rolling-ветку `live-data`. Ветка перезаписывается одним
коммитом, поэтому история `main` и размер Git не растут. Ручная сборка:

```bash
python tools/build_live_snapshot.py --output data/live/latest.json
```

Подробности реализации находятся в
[`research/eva-risk/README.md`](research/eva-risk/README.md).

## Воспроизведение ML-экспериментов

После подготовки локальных данных:

```bash
# Прогноз космической погоды: high-score профиль
python3 analysis/catboost_timeseries/train_catboost.py \
  --output-dir analysis/catboost_timeseries/output_v2

# Поиск high-recall режима при ограничении на precision
python3 analysis/catboost_timeseries/search_catboost_recall.py \
  --dataset analysis/catboost_timeseries/output_v2/catboost_timeseries_dataset.csv.gz \
  --output-dir analysis/catboost_timeseries/output_recall_search_existing

# Прогноз финального риска сближения по ESA CDM
python3 analysis/conjunction_ml/train_esa_cdm.py

# Инференс для CSV в схеме ESA CDM
python3 analysis/conjunction_ml/predict_cdm.py input.csv predictions.csv
```

Сырые архивы и тяжёлые промежуточные таблицы не входят в Git. Ссылки на
источники и команды загрузки приведены в [`data/README.md`](data/README.md).
